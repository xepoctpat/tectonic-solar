# Full solar-terrestrial pipeline + hypothesis monitor + UX overhaul

Three coordinated tracks. Scientific principle throughout: every new metric gets a citation/label, every threshold is a standard published one, and no fabricated data in research surfaces.

## Track 1 — Ingest the full coupling chain (data pipeline)

The hypothesized mechanism is: **Sun → solar wind (speed, density, Bz) → magnetopause pressure & reconnection → geomagnetic response (Kp, Dst, protons) → [hypothesized] seismicity**. Today only Kp storms reach the engine; Dst and protons are plumbed but never fetched; solar-wind history keeps only speed.

**1a. New pure module `public/src/js/solarMetrics.mjs`** (mirrors hypothesis-core.mjs's testable-pure-function pattern):
- `dynamicPressure(density, speed)` — P_dyn = 1.6726e-6 · n · v² [nPa] (standard formula)
- `electricFieldEy(speed, bzGsm)` — E_y = −v·Bz [mV/m] (merging electric field, the reconnection driver)
- `classifyPressure(pdyn)`, `classifyEy(ey)`, `classifyDst(dst)`, `classifyProtons(flux)` → standard bands (Pdyn: quiet <5 / elevated 5–10 / strong >10 nPa; Dst: quiet >−20 / moderate ≤−50 / intense ≤−100 nT; protons: S1 ≥10 pfu on ≥10 MeV; Ey: significant ≥3 mV/m)
- `detectDstStorms(records)` — Dst ≤ −50 onset→recovery event merging
- `detectPressurePulses(records)` — P_dyn jump ≥ +4 nPa within an hour or absolute ≥ 8 nPa
- Node-runnable; add `npm run test:solar-metrics` script with deterministic unit checks.

**1b. `spaceWeather.js` — fetch the two dead feeds + keep full history:**
- Fetch `NOAA_APIS.protonFlux` and `NOAA_APIS.dst` (shapes verified: Dst is hourly `{time_tag, dst}` rows; protons are `{time_tag, flux, energy}` — filter the `>=10 MeV` channel). Each gets a per-feed status entry following the existing live/degraded/stale/unavailable pattern, included in the localStorage last-good snapshot.
- Solar wind history now keeps `{time, speed, density, bt, bz, pdyn, ey}` (last 240 samples) instead of speed-only.
- Latest-value derived metrics (Pdyn, Ey) computed and stored in `spaceWeatherCache.solarWind`.

**1c. `db.js` — version bump to 2:**
- New `driverEvents` store: `{type: 'dst-storm'|'pressure-pulse'|'proton-event'|'x-flare', date, value, unit, source}` — the typed driver-event record the research engine can condition on. Live ingestion happens in spaceWeather.js after each poll (Kp≥5 storms keep their existing path); dayind archive storms keep `type` implied as today.
- New `dst` store for hourly Dst samples (90-day pruned) so the Dst chart and storm detection survive reloads.
- Existing stores untouched; `pruneOldRecords` extended.

## Track 2 — Wire the research engine to all drivers (the "simulation" part)

**2a. Storm definitions become selectable** (ROADMAP item "Dst-driven comparative storm thresholds"):
- `hypothesis-core.mjs`: `normalizeStormCatalog` gains an optional event-filter; no math changes to scan/assess (keeps hypothesis-sim green).
- `prediction.js runFullAnalysis({stormDefinition})` — `'kp'` (default, current behavior), `'dst'` (Dst≤−50 events), `'pressure'` (pressure pulses). Each definition's events come from IndexedDB (`storms` vs `driverEvents`).
- Research Lab: a storm-definition selector; verdicts per definition side by side in the workflow panel — the hypothesis must survive **all** driver definitions or say so (this is exactly "monitor all relevant kinds of solar input").
- `researchCompute.js`/sidecar unchanged for now (bootstrap still runs on the Kp corpus; Dst corpus bootstrap follows once the browser path is proven — noted honestly in UI).

**2b. "Coupling Chain Monitor" panel (new Space Weather card + Research Lab summary):**
- Visual chain: Solar wind → Magnetosphere → Ionosphere/Atmosphere → Lithosphere, each stage showing its live metric + status (speed/density/Pdyn/Ey; Kp/Dst/protons; weather/AQ where available; seismicity), and stages without a feed explicitly marked "no live feed — not monitored" (honest about the ionospheric link).
- Auto-updates with the 5-min space-weather cycle; each stage links to its data source label.
- Research Lab gets a compact "current drivers" readout so a researcher can see what regime the system is in while interpreting lag scans.

**2c. Dst + proton panels in Space Weather tab** (new cards: current Dst with band coloring, 24h sparkline; current ≥10 MeV proton flux with S-scale status), following the existing card/chart pattern (`charts.js` + `EMPTY_STATE_PLUGIN`).
